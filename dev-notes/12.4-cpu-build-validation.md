# 12.4 CPU Build Validation

## Environment

- Host: esnixi (NixOS)
- Architecture: x86-64
- Compiler: clang 21.1.8 (cc via NixOS)
- Flags: `-O3 -ffast-math -g -march=native -Wall -Wextra -std=c99 -D_GNU_SOURCE -fno-finite-math-only -DDS4_NO_GPU`

## Build Target

```
make cpu
```

This compiles all source files with `-DDS4_NO_GPU`, which disables all Metal/GPU code paths. The CPU build links only against `-lm -pthread` (no Metal frameworks, no CUDA libraries).

## Result

**PASS** — CPU build compiles without errors.

### Compilation Errors: 0
### Compilation Warnings Related to TensorOps: 0

### Pre-existing Warnings (unrelated to TensorOps)

- `clang: warning: argument unused during compilation: '-fno-finite-math-only'` — appears during link steps only; this is a pre-existing Makefile interaction between `-ffast-math` and the subsequent `-fno-finite-math-only` flag when passed to the linker driver.

No Metal, CUDA, or GPU-related libraries linked.

## TensorOps Isolation

- `DS4_NO_GPU` define properly guards all Metal/TensorOps code in `ds4.c`
- No Metal TensorOps symbols (`DS4_METAL_HAS_TENSOR`, `matmul2d`, `mpp`, Metal pipeline functions) appear in `ds4_cpu.o`
- The only "tensor" symbols in the CPU object are DS4's GGUF model-loading tensor validation functions (unrelated to Metal TensorOps)
- Metal stub functions (`ds4_engine_metal_graph_*_test`) compile to no-ops under `DS4_NO_GPU`

## Conclusion

The TensorOps changes (tasks 2–10) are fully guarded by `#ifdef __APPLE__` / `#ifndef DS4_NO_GPU` conditionals. The CPU build on Linux compiles cleanly and produces working binaries with no Metal code included. R18 is satisfied for the CPU build path.
