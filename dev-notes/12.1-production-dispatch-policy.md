# 12.1 — Production TensorOps Dispatch Policy

_Requirements: R9_

---

## 1. Runtime Conditions for TensorOps Dispatch

All TensorOps dispatch decisions derive from the layered conditions below.

### 1.1 Compile-Time: `DS4_METAL_HAS_TENSOR`

Injected into the Metal library via `MTLCompileOptions preprocessorMacros` when
`g_metal4_tensor_api_enabled` is true at library compilation time. Gates all
`#ifdef DS4_METAL_HAS_TENSOR` shader blocks:

- `metal/dense.metal` — dense prefill TensorOps kernels
- `metal/dsv4_misc.metal` — indexer score TensorOps kernel
- `metal/moe.metal` — attention-output low-rank + routed-expert TensorOps kernels

Host-side SDK tier macros (gate Objective-C API usage):

| Macro | SDK Version | Feature |
|-------|-------------|---------|
| `DS4_METAL_SDK_TENSOROPS` | macOS ≥ 26.0 | Basic tensor / matmul2d |
| `DS4_METAL_SDK_COOP_INPUT` | macOS ≥ 26.3 | Cooperative tensor as matmul input |
| `DS4_METAL_SDK_NATIVE_INT` | macOS ≥ 26.4 | Native int4/int8 tensor types |
| `DS4_METAL_SDK_NATIVE_LOWBIT` | macOS ≥ 27.0 | Low-bit float, E8M0, MX formats |

Legacy SDK builds (lacking these headers) compile the full legacy Metal backend
unchanged — no source edits required.

### 1.2 Runtime: `ds4_gpu_mpp_available()`

The unified runtime capability check. Returns true when ALL of:

1. **`g_metal4_tensor_api_enabled == 1`** — set during init when:
   - macOS ≥ 26.0 runtime is available
   - Device supports `MTLGPUFamilyMetal4`
   - Device name contains "M5", "M6", "A19", or "A20"
   - `ds4_gpu_compile_tensor_probe()` succeeds (minimal TensorOps pipeline test)
   - `DS4_METAL_DISABLE_METAL4` is NOT set
   - `DS4_METAL_DISABLE_TENSOROPS` is NOT set (global rollback)
2. **`!g_quality_mode`** — quality/reference mode routes to deterministic legacy
3. **`!g_tensorops_global_rollback`** — global rollback dominates all

### 1.3 Hardware: M5 Detection vs Pre-M5

| Detection | Result |
|-----------|--------|
| Device name matches "M5", "M6", "A19", "A20" | M5-class → TensorOps auto-enabled |
| `MTLGPUFamilyMetal4` supported but name doesn't match | Pre-M5 → legacy default (TensorOps not auto-enabled) |
| No Metal4 family | Pre-M5 → legacy only |

Pre-M5 Apple Silicon explicitly excluded from TensorOps auto-enable. No TensorOps
on older GPUs without device-specific evidence (R17).

### 1.4 Per-Operation: `mpp_mask` Bits

`ds4_gpu_routed_mm_mpp_mask()` returns `ds4_gpu_mpp_available() ? 7 : 0`.

| Bit | Operation |
|-----|-----------|
| 1 | MoE gate projection |
| 2 | MoE up projection |
| 4 | MoE down projection |

All three bits are set when TensorOps is available (no per-operation partial disable
via the mask itself). Per-operation rollback is handled by separate environment
variables (see §2).

### 1.5 Per-Quant Dispatch

TensorOps kernels exist for the following quant formats:

| Quant | Dense Prefill | Indexer | MoE Gate/Up | MoE Down |
|-------|---------------|---------|-------------|----------|
| F16 | ✅ `kernel_mul_mm_f16_f32_mpp_direct_rhs` | ✅ (staging) | — | — |
| Q8_0 | ✅ `kernel_mul_mm_q8_0_f32_nax_direct_rhs` | — | — | — |
| Q4_0 | ✅ `kernel_mul_mm_q4_0_f32_nax_direct_rhs` | — | — | — |
| Q4_K | ✅ `kernel_mul_mm_q4_K_f32_nax_direct_rhs` | — | ✅ `kernel_mul_mm_id_q4_K_mpp_pair_swiglu_f16` | ✅ `kernel_mul_mm_id_q4_K_f16_mpp` |
| MXFP4 | — | — | ✅ `kernel_mul_mm_id_mxfp4_mpp_pair_swiglu_f16` | ✅ `kernel_mul_mm_id_mxfp4_f16_mpp` |
| IQ2_XXS | — | — | ✅ `kernel_mul_mm_id_iq2_xxs_f32_mpp` | ✅ `kernel_mul_mm_id_iq2_xxs_f16_mpp` |
| Q2_K | — | — | — | ✅ `kernel_mul_mm_id_q2_K_f16_mpp` |

Quant formats without a TensorOps variant use the legacy simdgroup kernel unconditionally.

### 1.6 Shape: Batch Size Threshold

| Zone | N range | Dense path | MoE path |
|------|---------|-----------|----------|
| Batch-1 decode | N = 1 | Legacy matvec | Legacy matvec (`kernel_mul_mv_*`) |
| Tiny pair | N = 2–5 | Small-batch / mul_mv_ext | Fused pair matvec (`mul_mv_id_*_pair_swiglu`) |
| Gap zone | N = 6–31 | Small-batch / mul_mv_ext | Per-token matvec (pending crossover) |
| Prefill | N ≥ 32 | TensorOps candidate | Grouped matmul (`use_mm_id`) + TensorOps |

**Default crossover:** N ≥ 32 for `use_mm_id`.

**Override:** `DS4_METAL_TENSOROPS_CROSSOVER_N=<value>` lowers the threshold for
benchmarking (minimum 6, protects the tiny pair zone). Pending task 10.2 measurement.

**Dense-specific:** TensorOps requires `n_tok ≥ 32` AND alignment checks (below).

**Indexer-specific:** TensorOps requires `n_tokens ≥ 16`.

### 1.7 Alignment Requirements

| Quant | in_dim | out_dim | n_tok |
|-------|--------|---------|-------|
| F16 | % 32 == 0 | % 64 == 0 | % 32 == 0 (or split-prefix) |
| Q8_0 | % 64 == 0 | % 64 == 0 | % 32 == 0 (or split-prefix if n_tok ≥ 192) |
| Q4_0 | % 64 == 0 | % 64 == 0 | % 32 == 0 |
| Q4_K | % 64 == 0 | % 64 == 0 | % 32 == 0 |
| Indexer | head_dim == 128 | — | n_tokens ≥ 16 |
| Attn-out low-rank | — | — | n_tokens ≥ 32, n_tokens % 64 == 0 |

Alignment failures fall through to legacy.

### 1.8 Streaming / SSD Mode Exclusion

When SSD streaming is active, TensorOps is excluded from MoE routed projections:

| Streaming case | Exclusion mechanism | Fallback |
|---------------|--------------------|---------| 
| IQ2_XXS streaming prefill | `use_iq2_batch_selected_addr` blocks `use_mm_id` | Addr-based matvec kernels |
| Q4_K streaming prefill | `use_q4_batch_expert_table` blocks `use_mm_id` | Table-based matvec kernels |
| MXFP4 streaming prefill | `ds4_gpu_wrap_model_range()` returns nil | Function returns 0 (graceful) |
| Any streaming decode (N=1) | Batch function not called | Slot-based matvec (`_slots6_*`) |

TensorOps routed kernels require contiguous model-map or resident-cache layouts.
SSD streaming uses address-table or slot-based access patterns that are incompatible.

**Dense TensorOps is unaffected by SSD streaming** — dense projections always have
contiguous weight buffers.

### 1.9 Quality Mode

`--quality` / `g_quality_mode = true`:
- Suppresses `ds4_gpu_mpp_available()` → all TensorOps disabled
- Routes to deterministic legacy kernels (F32 for indexer, standard simdgroup for dense/MoE)
- Purpose: maximum numerical reproducibility for comparison/debugging

### 1.10 Tensor Parallelism

`g_tp_split_world == 2` blocks the fused pair+SwiGLU matmul dispatch (both
simdgroup and TensorOps). This is a conservative host-side guard. Some TensorOps
kernels have the GPU-side `ds4_tp_owns_expert()` check, but the host blocks them
regardless at TP > 1.

## 2. Rollback Hierarchy

Rollback always dominates force-enables. The hierarchy is strict:

### 2.1 Global Rollback

| Variable | Effect |
|----------|--------|
| `DS4_METAL_DISABLE_TENSOROPS` | Zeros ALL TensorOps capability flags. Sets `g_tensorops_global_rollback = 1`, clears `g_metal4_tensor_api_enabled`, `g_tensorops_coop_input_available`, `g_tensorops_native_int4_int8_available`, `g_tensorops_native_lowbit_float_available`, `g_tensorops_native_e8m0_scale_available`. Every TensorOps path falls to legacy. |
| `DS4_METAL_DISABLE_METAL4` | Prevents Metal4 family detection at init → `g_metal4_tensor_api_enabled = 0`. Same effect as global rollback but at the capability detection level. |

### 2.2 Per-Operation Rollback (MoE Gate/Up)

| Variable | Effect |
|----------|--------|
| `DS4_METAL_DISABLE_MXFP4_MOE_GATE_UP_MPP` | Disables `kernel_mul_mm_id_mxfp4_mpp_pair_swiglu_f16`, falls back to simdgroup pair kernel |
| `DS4_METAL_DISABLE_Q4_K_PAIR_SWIGLU_MPP` | Disables `kernel_mul_mm_id_q4_K_mpp_pair_swiglu_f16`, falls back to simdgroup pair kernel |

### 2.3 Per-Operation Rollback (MoE Down)

| Variable | Effect |
|----------|--------|
| `DS4_METAL_DISABLE_MXFP4_MOE_DOWN_MPP` | Disables `kernel_mul_mm_id_mxfp4_f16_mpp`, falls back to simdgroup down kernel |
| `DS4_METAL_DISABLE_Q4_K_MOE_DOWN_MPP` | Disables `kernel_mul_mm_id_q4_K_f16_mpp`, falls back to simdgroup down kernel |

### 2.4 Dominance Rules

```
DS4_METAL_DISABLE_TENSOROPS (global)
  └── dominates ALL per-operation disables
      └── DS4_METAL_DISABLE_MXFP4_MOE_GATE_UP_MPP
      └── DS4_METAL_DISABLE_Q4_K_PAIR_SWIGLU_MPP
      └── DS4_METAL_DISABLE_MXFP4_MOE_DOWN_MPP
      └── DS4_METAL_DISABLE_Q4_K_MOE_DOWN_MPP
```

Global rollback zeroes `mpp_mask` → per-operation checks are moot.
Per-operation rollback uses `getenv()` checks AFTER the global
`mpp_mask` gate, so they disable specific paths without affecting others.

**Rollback always wins over force-enables.** There are no user-facing force-enable
flags that can override a rollback. The only "force-enable" is the absence of a
disable variable (the fastest M5 path auto-enables without any env var).

### 2.5 Additional Override

| Variable | Effect |
|----------|--------|
| `DS4_METAL_TENSOROPS_CROSSOVER_N` | Overrides N≥32 MoE grouped-matmul threshold (min 6). Development/benchmark use. Does not override global rollback. |

## 3. Dispatch Decision Tree by Operation Class

### 3.1 Dense Prefill Projection

```
ds4_gpu_matmul_{f16,q8_0,quant}_tensor(out, ..., n_tok)
  │
  ├─ n_tok == 1
  │   ├─ Q8_0 + prefer_decode_mpp + mpp_available + in_dim%64==0
  │   │   → "kernel_mul_mm_q8_0_f32_nax_direct_rhs" (NR1=32, single-token)
  │   └─ else → legacy matvec kernel
  │
  ├─ n_tok ≤ {8–16}
  │   → mul_mv_ext small-batch path (legacy)
  │
  └─ n_tok ≥ 32 (prefill)
      ├─ ds4_gpu_mpp_available()? NO → legacy simdgroup matmul
      ├─ alignment checks pass? NO → legacy simdgroup matmul
      ├─ pipeline lookup succeeds? NO → ds4_gpu_warn_mpp_fallback() → legacy
      │
      ├─ Tile selection:
      │     n_tok % 128 == 0 → NR1 = 128
      │     n_tok %  64 == 0 → NR1 = 64
      │     else             → NR1 = 32
      │
      ├─ [Q8_0 only] Split-prefix logic:
      │     n_tok ≥ 192 && n_tok%32 != 0 → TensorOps prefix + legacy tail
      │     n_tok < 192 && n_tok%32 != 0 → full legacy
      │
      └─ Encode: kernel_mul_mm_{quant}_f32_nax_direct_rhs{_n64,_n128}
          Grid: (n_tok/tile_n) × (out_dim/64) × 1
          Threads: 128 × 1 × 1
```

### 3.2 Indexer Scoring

```
ds4_gpu_indexer_scores_prefill_tensor(...)
  │
  ├─ head_dim != 128 → ERROR (hard constraint)
  │
  ├─ g_quality_mode → kernel_dsv4_indexer_scores_tiled_f32 (F32 legacy)
  │
  ├─ ds4_gpu_mpp_available() && n_tokens >= 16
  │   → kernel_dsv4_indexer_scores_nax
  │     Tile: 16 tokens × 32 compressed rows × 128D, 4 SIMD groups
  │
  └─ else → kernel_dsv4_indexer_scores_tiled (half-precision legacy)
```

### 3.3 MoE Gate/Up Prefill

```
ds4_gpu_routed_moe_batch_tensor(...)
  │
  ├─ use_iq2_batch_selected_addr? (streaming)
  │   → addr-based streaming kernels; TensorOps EXCLUDED
  │
  ├─ use_q4_batch_expert_table? (streaming/table)
  │   → table-based kernels; TensorOps EXCLUDED
  │
  ├─ n_tokens < ds4_gpu_moe_mm_id_threshold() (default 32)
  │   ├─ N ≤ 5 && tiny pair available → fused pair matvec
  │   └─ else → per-token matvec
  │
  └─ use_mm_id (n_tokens ≥ threshold):
      ├─ use_mm_id_pair_swiglu? (g_tp_split_world != 2 && request_mid_f16 && ...)
      │   │
      │   ├─ gate_type == MXFP4 && (mpp_mask & 3) &&
      │   │   !use_mxfp4_mm_id_pair_swiglu_compact_tile &&
      │   │   DS4_METAL_DISABLE_MXFP4_MOE_GATE_UP_MPP not set
      │   │   → kernel_mul_mm_id_mxfp4_mpp_pair_swiglu_f16 (TensorOps)
      │   │
      │   ├─ gate_type == Q4_K && (mpp_mask & 3) &&
      │   │   DS4_METAL_DISABLE_Q4_K_PAIR_SWIGLU_MPP not set
      │   │   → kernel_mul_mm_id_q4_K_mpp_pair_swiglu_f16 (TensorOps)
      │   │
      │   ├─ gate_type == IQ2_XXS && (mpp_mask & 3) == 3
      │   │   → kernel_mul_mm_id_iq2_xxs_f32_mpp (TensorOps, both operands staged)
      │   │
      │   └─ else → legacy simdgroup pair kernel
      │
      └─ separate gate/up/down dispatch (non-fused fallback)
```

### 3.4 MoE Down Prefill

```
ds4_gpu_routed_moe_batch_tensor(...)  [down projection section]
  │
  ├─ Streaming excluded (same as gate/up — addr/table paths block use_mm_id)
  │
  ├─ (mpp_mask & 4) && request_mid_f16 &&
  │   down_type == MXFP4 &&
  │   DS4_METAL_DISABLE_MXFP4_MOE_DOWN_MPP not set &&
  │   pipeline lookup succeeds
  │   → kernel_mul_mm_id_mxfp4_f16_mpp (TensorOps)
  │
  ├─ (mpp_mask & 4) && request_mid_f16 &&
  │   down_type == Q4_K &&
  │   DS4_METAL_DISABLE_Q4_K_MOE_DOWN_MPP not set &&
  │   pipeline lookup succeeds
  │   → kernel_mul_mm_id_q4_K_f16_mpp (TensorOps)
  │
  ├─ (mpp_mask & 4) && request_mid_f16 &&
  │   down_type == IQ2_XXS/Q2_K
  │   → kernel_mul_mm_id_{iq2_xxs,q2_K}_f16_mpp (TensorOps)
  │
  └─ else → legacy simdgroup down kernel
```

### 3.5 Decode (All Operations)

```
N = 1 (batch-1 decode)
  │
  ├─ Dense: legacy matvec (kernel_mul_mv_*)
  │   Exception: Q8_0 with prefer_decode_mpp=true can use TensorOps
  │              (not the public default — internal-only for comparison)
  │
  ├─ Indexer: legacy tiled kernel
  │
  ├─ MoE: slot-based matvec (kernel_mul_mv_slots6_*)
  │        or fused decode pair (kernel_mul_mv_id_*_pair_swiglu)
  │
  └─ Invariant: batch-1 is bandwidth-bound; TensorOps not default (R10)
```

### 3.6 Small-Batch / Speculative Verification

```
N = 2–31 (verify batch, session batch, prompt tails)
  │
  ├─ N ≤ 5: tiny pair path (fused gate/up matvec)
  │
  ├─ N = 6–31: per-token matvec (current default)
  │   Pending: DS4_METAL_TENSOROPS_CROSSOVER_N may lower threshold
  │
  └─ N ≥ crossover (default 32): grouped matmul + TensorOps
```

## 4. Attention-Output Low-Rank Projection

A separate dispatch path exists for the attention-output low-rank projection:

```
ds4_gpu_use_mpp_attn_out_low_matmul():
  = ds4_gpu_mpp_available()

Conditions for TensorOps:
  - mpp_available
  - n_tokens >= 32
  - n_tokens % 64 == 0
  - Q8_0 or Q4_K weight type

Kernels:
  - kernel_attn_out_low_q8_0_mpp_direct_rhs_n64
  - kernel_attn_out_low_q4_K_mpp_direct_rhs_n64

Fallback: legacy attention-output kernel
```

## 7. Init-Time Capability Detection Sequence

```
ds4_gpu_init()
  │
  ├─ ds4_gpu_detect_capabilities()
  │   ├─ Check MTLGPUFamilyMetal4 support
  │   ├─ Check device name for M5/M6/A19/A20
  │   ├─ ds4_gpu_compile_tensor_probe() → compile+create minimal pipeline
  │   ├─ If all pass: g_metal4_tensor_api_enabled = 1
  │   ├─ Check SDK tiers for cooperative input, native int, native lowbit
  │   └─ Set corresponding g_tensorops_*_available flags
  │
  ├─ ds4_gpu_apply_tensorops_rollback()
  │   ├─ Check DS4_METAL_DISABLE_TENSOROPS env
  │   └─ If set: zero ALL capability flags (g_metal4_tensor_api_enabled = 0, etc.)
  │
  ├─ Compile Metal library with DS4_METAL_HAS_TENSOR if g_metal4_tensor_api_enabled
  │
  └─ Pipeline lazy creation (on first dispatch)
```

## 9. Key Invariants

1. **Fastest M5 path requires no user env var.** Auto-enables through capability detection.
2. **Rollback always dominates force-enable.** No env var can force TensorOps when a
   higher-level disable is set.
3. **Batch-1 decode is NEVER TensorOps by default** (R10). Bandwidth-bound operations
   stay on hand-tuned matvec.
4. **Quality mode routes everything to legacy** for maximum reproducibility.
5. **Pipeline lookup failure triggers graceful fallback**, not a crash.
6. **Streaming exclusion is structural** — the `use_mm_id` gate is false when streaming
   paths are active, preventing TensorOps selection before any quant-specific check.
7. **Pre-M5 hardware never gets TensorOps auto-enabled** without device-specific
   benchmark evidence (R17).
8. **Compact-tile path (pre-M5 optimization) blocks TensorOps selection** via the
   `!use_mxfp4_mm_id_pair_swiglu_compact_tile` guard on M5 this is never set.
