# 11.1 — Post-MoE TensorOps Prefill Trace Plan

## Status: PENDING HARDWARE EXECUTION

This task requires Apple Silicon hardware with Metal System Trace / Instruments
profiling capability. It cannot be executed on the current NixOS workstation.

---

## Purpose

Tasks 7–8 accelerated routed-MoE gate/up/down expert projections with TensorOps.
The prefill bottleneck profile has therefore shifted. This trace captures the new
profile to determine whether attention operations are now the dominant bottleneck,
informing the decision in task 11.2 (whether attention merits TensorOps work).

---

## Method

### Capture tool

Metal System Trace via Instruments or `xctrace record` with the Metal System Trace
template. The trace must cover a full 8K-token prefill pass.

### Command (example)

```bash
xctrace record --template 'Metal System Trace' \
  --output post-moe-8k-prefill.trace \
  --launch -- ./ds4-bench \
    -m ds4flash.gguf \
    --prompt-file speed-bench/promessi_sposi.txt \
    --ctx-start 8192 \
    --ctx-max 8192 \
    --step-incr 8192 \
    --gen-tokens 0
```

Alternatively, use Instruments.app with the Metal System Trace template and attach
to `ds4-bench` or a single-prompt `ds4-cli` run.

### Warm-up

Run at least one throwaway prefill before the profiled pass to avoid capturing
cold-cache/pipeline-compilation overhead.

---

## What to Capture

For every GPU kernel dispatch during the 8K prefill:

1. **Per-kernel GPU time** — wall-clock GPU occupancy per dispatch
2. **Dispatch gaps** — idle time between kernel dispatches (launch overhead / host sync)
3. **Synchronization stalls** — encoder/command-buffer waits, fence waits
4. **Memory bandwidth utilization** — read/write GB/s per kernel where available
5. **TensorOps / Neural Accelerator activity** — if exposed by the trace template,
   confirm TensorOps dispatches use the M5 matrix units

Group results by pipeline stage:
- Dense projections (QKV, output)
- Indexer scoring (ratio-4 compressed attention)
- MoE gate/up (routed expert)
- MoE down (routed expert)
- FlashAttention / attention kernel
- Softmax / normalization
- Router / gating
- Other (embedding, RoPE, residual add, etc.)

---

## What to Look For

1. **Has MoE dropped from the top of the profile?**
   After TensorOps lift, gate/up/down should consume significantly less GPU time
   than in the task 1.4 baseline trace.

2. **Is attention now the primary bottleneck?**
   FlashAttention, indexer scoring, or compressed-attention kernels may now be #1.

3. **Are dense projections material?**
   QKV/output projections were already TensorOps-lifted (task 3). Confirm they
   remain fast and haven't regressed.

4. **Are there new synchronization or launch-gap issues?**
   TensorOps may introduce different command-buffer submission patterns.

5. **Is any stage unexpectedly bandwidth-bound?**
   Weight streaming or activation memory traffic may dominate smaller kernels
   now that the large MoE compute is faster.

## Expected Outcome

Based on the TensorOps work in tasks 7–8:

- **MoE gate/up/down** should drop significantly in GPU time percentage (target: no
  longer in top-2 for a balanced 8K prefill)
- **Attention** (FlashAttention / indexer / compressed attention) is the most likely
  new #1 bottleneck, since it was not accelerated in tasks 3–8
- **Dense projections** should remain fast (already TensorOps-lifted in task 3)
- **Router/gating** and **normalization** are typically cheap but may become relatively
  more visible as large matmuls get faster

If attention is NOT the top bottleneck, the remaining bottleneck (likely dense
projections, indexer scoring, or dispatch overhead) becomes the target, and task 11.2
may defer attention TensorOps work entirely per stop condition 14.6.

---

## Decision Criteria for Task 11.2

After this trace is captured, apply the following rules:

- If attention stages occupy **>25%** of prefill GPU time → proceed with attention
  TensorOps investigation (task 11.3)
- If attention stages occupy **15–25%** → evaluate whether the absolute time saving
  justifies the complexity; may still proceed
- If attention stages occupy **<15%** → defer attention work per stop condition 14.6;
  focus hardening effort elsewhere (task 12)
