# Task 4.4 — Indexer Production Policy (Locked)

## 1. Policy Summary

The indexer TensorOps path (`kernel_dsv4_indexer_scores_nax`) is **production-default on M5** with no user intervention required. This task documents the locked policy and adds dispatch counters.

| Condition | Kernel | Notes |
|-----------|--------|-------|
| M5 + `mpp_available` + `n_tokens >= 16` + `head_dim == 128` | `kernel_dsv4_indexer_scores_nax` | TensorOps / matmul2d, 4 SIMD groups |
| M5 + `mpp_available` + `n_tokens < 16` | `kernel_dsv4_indexer_scores_tiled` | Legacy tiled, shape too small for TensorOps |
| Pre-M5 (or `mpp_available == false`) | `kernel_dsv4_indexer_scores_tiled` | Legacy tiled (default) |
| `--quality` mode (any hardware) | `kernel_dsv4_indexer_scores_tiled_f32` | Full-precision legacy |
| `DS4_METAL_DISABLE_TENSOROPS=1` | `kernel_dsv4_indexer_scores_tiled` | Global rollback forces legacy |

---

## 2. Winning Tile Shape

**16 tokens × 32 compressed rows × 128D** with 4 SIMD groups (128 threads per threadgroup).

The code comment records: *"16-token × 32-row tile was the winning NAX shape in local sweeps. A wider 64-row compressed tile increased setup/cache pressure and was slower despite doing more work per dispatch."*

Task 4.2 did not produce formal benchmark data that would justify changing the tile. The current shape remains locked.

---

## 3. Admission Logic

Expressed in code (`ds4_metal.m`):

```c
const bool mpp_ok = ds4_gpu_mpp_available();
const bool use_nax = mpp_ok && n_tokens >= 16u;
```

Where `ds4_gpu_mpp_available()` requires:
1. `g_metal4_tensor_api_enabled == 1` (compiled + runtime M5 detection + pipeline probe success)
2. `!g_quality_mode`
3. `!g_tensorops_global_rollback` (i.e. `DS4_METAL_DISABLE_TENSOROPS` not set)

Additional hard constraint checked earlier in the function:
- `head_dim == 128` (exits with error if violated)

## 4. Dispatch Counters (Added in Task 4.4)

At the indexer dispatch point, the following counters are incremented:

| Path taken | Counter incremented |
|------------|-------------------|
| TensorOps selected | `g_ctr_indexer_tensorops` |
| `mpp_available` false (pre-M5, rollback, quality) | `g_ctr_fallback_os` |
| mpp available but `n_tokens < 16` | `g_ctr_fallback_shape` |

These are relaxed atomics with negligible overhead, consistent with the counter infrastructure from Task 2.3.

---

## 5. Legacy Fallback (Clean)

The fallback path is deterministic and requires no cleanup:

- **Half-precision tiled** (`kernel_dsv4_indexer_scores_tiled`): 8 tokens × 32 rows, simdgroup matrix multiply, half staging. This is the pre-M5 production default.
- **Full-precision tiled** (`kernel_dsv4_indexer_scores_tiled_f32`): Same tile geometry, F32 throughout. Selected by `--quality` mode for maximum numerical reproducibility.

Both legacy kernels produce identical final scores (weighted-ReLU accumulation + causal masking). They differ only in intermediate precision.

No dead code or stale experimental paths exist in the indexer dispatch. The `use_nax` boolean and the quality-mode check are the only two branches.

---

## 6. Cooperative Post-Processing (Rejected — Task 4.3)

Task 4.3 investigated fusing weighted ReLU accumulation with the cooperative tensor output to avoid materializing the `dot` buffer. This was **rejected** because weighted ReLU requires per-element max(x, 0) and a head-specific weight multiply — operations that cannot be expressed as a cooperative tensor transformation without breaking the store contract.

The current design stores to threadgroup `dot`, then each thread reads its share for weighted-ReLU accumulation. This remains the production path.

---

## 7. Integration with Capability Layer (Task 2.x)

The indexer dispatch uses `ds4_gpu_mpp_available()` which is the unified runtime capability check established in Task 2.2. This function encapsulates:

- Compile-time feature availability (`DS4_METAL_HAS_TENSOR`)
- Runtime M5 detection
- Pipeline probe success
- Global rollback override (`DS4_METAL_DISABLE_TENSOROPS`)
- Quality mode exclusion

No additional per-operation rollback variable (e.g. `DS4_METAL_DISABLE_M5_TENSOROPS_INDEXER`) has been added. The global rollback is sufficient for the indexer since it has a single TensorOps path with a simple, proven fallback.
