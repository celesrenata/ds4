# 0.4 Toolchain Capability Matrix

## Status

**Environment:** NixOS (Linux) — no local macOS, Xcode, or Metal compiler available.  
**Action required:** Actual toolchain probing must be performed on macOS hardware (M5 target).  
This document records what the codebase reveals about SDK/OS version checks, Metal language
version selection, GPU family detection, and TensorOps feature tier gating.

---

## 1. Metal Language Version Selection

DS4 does **not** explicitly set a Metal language version (`-std=metal*` or
`MTLCompileOptions.languageVersion`). The project relies on the SDK default:

- `MTLCompileOptions *options = [MTLCompileOptions new]` — no `languageVersion` override.
- The Metal compiler infers the language version from the installed SDK.
- On macOS 26+ SDK, this means Metal 4 language features (tensor types, MPP) are
  available implicitly when the corresponding headers exist.

**Where this happens:** `ds4_metal.m` line ~6402.

---

## 2. Compile-Time Feature Gating

The single compile-time gate is the macOS SDK version macro:

```c
#if defined(__MAC_OS_X_VERSION_MAX_ALLOWED) && __MAC_OS_X_VERSION_MAX_ALLOWED >= 260000
```

This guards:
- `ds4_gpu_compile_tensor_probe()` — the Metal source compile probe
- `ds4_gpu_detect_metal4_features()` — all Metal 4 runtime detection

**Effect:** On SDK < macOS 26.0, the entire TensorOps path is compiled out. The legacy
Metal backend builds without source changes.

**No additional SDK tier checks exist yet** for:
- macOS 26.3 (cooperative tensor as matmul input)
- macOS 26.4 (native int4/int8 tensor types)
- macOS 27 (low-bit float, E8M0 scale planes, MX formats)

These will need future `__MAC_OS_X_VERSION_MAX_ALLOWED >= 263000` (etc.) guards or
runtime `@available(macOS 26.3, *)` checks.

## 3. Runtime Capability Detection

### GPU Family Detection

```objc
[g_device supportsFamily:MTLGPUFamilyMetal4]  // g_metal4_family_supported
[g_device respondsToSelector:@selector(newMTL4CommandQueue)]  // g_metal4_queue_supported
```

### M5 / Neural Accelerator Detection

Device name string matching (not GPU family enumeration):

```c
ds4_gpu_device_name_contains("M5")   → g_metal4_m5_neural_accelerators_hint
```

Pre-M5 detection:

```c
strncmp(g_metal_device_name, "Apple M", 7) == 0 && g_metal_device_name[7] >= '1' && <= '4'
```

### TensorOps Auto-Enable Policy

TensorOps is auto-enabled only on:
- M5, M6, A19, A20 devices (the `default_enable` set)
- After the compile probe passes

Pre-M5 Metal 4 capable hardware does NOT auto-enable TensorOps.

### Compile Probe

`ds4_gpu_compile_tensor_probe()` compiles a minimal kernel at runtime:
- Includes `<metal_tensor>` and `<MetalPerformancePrimitives/MetalPerformancePrimitives.h>`
- Uses `tensor`, `matmul2d`, `matmul2d_descriptor`, cooperative tensor, `dextents`, `slice`
- Creates a full pipeline state to confirm the driver/GPU support the feature

This validates **Tier 1: basic TensorOps** (see below).

## 4. Feature State Variables

| Variable | Type | Meaning |
|----------|------|---------|
| `g_metal4_runtime_available` | int | macOS 26+ runtime detected |
| `g_metal4_family_supported` | int | Device supports `MTLGPUFamilyMetal4` |
| `g_metal4_queue_supported` | int | Device has `newMTL4CommandQueue` selector |
| `g_metal4_m5_neural_accelerators_hint` | int | M5 device name + Metal4 family |
| `g_metal4_tensor_api_enabled` | int | TensorOps compile probe passed AND default-enable device |
| `g_metal4_tensor_api_compile_supported` | int | Compile probe passed (may not be auto-enabled) |

### Dispatch Gate

```c
static int ds4_gpu_mpp_available(void) {
    return g_metal4_tensor_api_enabled && !g_quality_mode;
}
```

Quality mode (`--quality`) disables TensorOps to preserve bit-identical legacy behavior.

---

## 5. DS4_METAL_HAS_TENSOR Preprocessor Macro

Defined as a compile-time preprocessor macro passed via `MTLCompileOptions.preprocessorMacros`
when `g_metal4_tensor_api_enabled` is true at Metal library compilation time.

Guards TensorOps shader code in:
- `metal/dense.metal` — `kernel_mul_mm_mpp_direct_rhs` (F16, Q4_0, Q4_K, Q8_0 × 32/64/128 token tiles)
- `metal/dsv4_misc.metal` — `kernel_dsv4_indexer_scores_nax` (ratio-4 indexer)
- `metal/moe.metal` — `kernel_attn_out_low_mpp_direct_rhs` (attention output low-rank projection)
                     — `kernel_mul_mm_id_*_mpp` (MoE staged TensorOps: IQ2_XXS, Q2_K)

## 6. TensorOps Feature Tiers (Design Reference)

| Tier | OS/SDK | Feature | Current Probe? |
|------|--------|---------|----------------|
| 1 | macOS 26.0+ | `tensor`, `matmul2d`, cooperative destination, inline tensor | **YES** — compile probe |
| 2 | macOS 26.3+ | Cooperative tensor as matmul **input** (custom dequant → matmul) | **NO** — not yet probed |
| 3 | macOS 26.4+ | Native int4/int8 tensor element types | **NO** — not yet probed |
| 4 | macOS 27+ | Low-bit float tensors, E8M0 scale planes, MX multi-plane | **NO** — not yet probed |

Task 2.1 will add compile-time guards; Task 2.2 will add runtime probes for tiers 2–4.

## 8. Dispatch Conditions

`ds4_gpu_mpp_available()` is checked at each dispatch site with additional shape guards:

| Dispatch Site | Additional Condition |
|---------------|---------------------|
| Dense prefill | `n_tok >= 32` AND `in_dim % 64 == 0` (some: `% 32 == 0`) |
| Indexer NAX | `n_tokens >= 16` |
| Attention output low-rank | `ds4_gpu_use_mpp_attn_out_low_matmul()` |
| Routed MoE | `ds4_gpu_routed_mm_mpp_mask()` returns bitmask (currently IQ2/Q2_K only) |
| Decode (batch-1) | Some paths check `ds4_gpu_mpp_available()` with `prefer_decode_mpp` |

## 9. Environment Variable Controls

| Variable | Effect |
|----------|--------|
| `DS4_METAL_DISABLE_METAL4` | Disables all Metal 4 feature detection |
| `DS4_METAL_MATH_SAFE` | Forces strict IEEE-754 (disables fast-math) |
| `DS4_METAL_DISABLE_PRE_M5_DECODE_PORTS` | Disables ported decode features on M1–M4 |

No unified `DS4_METAL_DISABLE_TENSOROPS` rollback exists yet (Task 2.4 will add one).

## 11. Stub Compile Probes

Created at: `tests/probes/probe_tensorops_tier1.metal` through `_tier4.metal`

These are minimal Metal source files that can be compiled on macOS to verify
SDK availability of each feature tier. They cannot be tested on this Linux
environment but are ready for macOS execution via:

```bash
xcrun metal -c tests/probes/probe_tensorops_tier1.metal -o /dev/null
xcrun metal -c tests/probes/probe_tensorops_tier2.metal -o /dev/null
xcrun metal -c tests/probes/probe_tensorops_tier3.metal -o /dev/null
xcrun metal -c tests/probes/probe_tensorops_tier4.metal -o /dev/null
```

A failure at any tier means that tier's features are not available in the
installed SDK/toolchain.
