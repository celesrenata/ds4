# Task 4.1 — `kernel_dsv4_indexer_scores_nax` End-to-End Trace

## 1. Overview

The kernel implements the regular matrix-core portion of DeepSeek-V4 ratio-4 compressed-attention indexer scoring using Metal TensorOps / `matmul2d`. It computes per-token, per-compressed-row dot products over D=128 dimensions, applies weighted ReLU accumulation across all indexer heads, and writes the final fused score matrix consumed by a separate top-k selection pass.

**Location:** `metal/dsv4_misc.metal:6333`  
**Host dispatch:** `ds4_metal.m:17781` (`ds4_gpu_indexer_scores_batch_tensor`)

---

## 2. Tile Dimensions

| Symbol | Value | Meaning |
|--------|-------|---------|
| `TM`   | 16    | Token tile (rows of output per threadgroup) |
| `TQ`   | 32    | Total Q rows per matmul = 2 × TM (paired heads) |
| `TN`   | 32    | Compressed-row tile (columns of output per threadgroup) |
| `NK`   | 32    | K-step per matmul iteration (reduction width per pass) |
| `D`    | 128   | Full head dimension (sum of all K-steps: 4 × 32 = 128) |
| `NUM_THREADS` | 128 | Threads per threadgroup (4 SIMD groups) |

The kernel comment notes that "16-token × 32-row tile was the winning NAX shape in local sweeps. A wider 64-row compressed tile increased setup/cache pressure and was slower despite doing more work per dispatch."

---

## 3. Operand Staging

### 3.1 Threadgroup memory layout

```
shared[0 .. 2*TQ*NK)           → qtg: double-buffered Q tile (2 × [32][32] half)
shared[2*TQ*NK .. +TN*D)       → ktg: K staging tile ([32][128] half)
shared[2*TQ*NK + TN*D .. +TQ*TN) → dot: cooperative-store target ([32][32] float, column-major)
```

Total threadgroup allocation (set by host):
- Q:   `2 × 32 × 32 = 2048` halfs = 4096 bytes
- K:   `32 × 128 = 4096` halfs = 8192 bytes
- dot: `32 × 32 = 1024` floats = 4096 bytes
- **Total: 16384 bytes**

### 3.2 K staging (compressed rows)

K is loaded once per threadgroup into `ktg`. Each of 32 compressed rows is loaded by 4 threads (one thread handles 32 consecutive floats → 8 float4 loads), converted to half4 on write. This is a full-tile cooperative load with float→half conversion.

### 3.3 Q staging (query rows, double-buffered)

Q is staged per k-step loop iteration. Each thread loads one row of 8 consecutive floats (float4 × 2 → half4 × 2) for one specific (head, token) pair within the 32-row Q tile. The double buffer (`qtg` / `qtg + TQ*NK`) allows overlapping the next k-step's staging with the current matmul.

### 3.4 Paired-head processing

The Q tile has TQ=32 rows covering 2 heads × TM=16 tokens. Row indices `[0..15]` are head 0 tokens, `[16..31]` are head 1 tokens. This halves the dispatch count versus single-head processing while keeping the matmul shape constant.

## 4. Matmul Descriptor and Cooperative Tensor Usage

### 4.1 Tensor construction

```metal
auto tq0 = tensor(qtg,          dextents<int32_t, 2>(NK, TQ));   // [32][32] half
auto tq1 = tensor(qtg + TQ*NK,  dextents<int32_t, 2>(NK, TQ));   // [32][32] half (double buffer)
auto tk  = tensor(ktg,          dextents<int32_t, 2>(D, TN));     // [128][32] half
auto td  = tensor(dot,          dextents<int32_t, 2>(TQ, TN),     // [32][32] float, column-major
                  array<int, 2>({1, TQ}));
```

All tensors are constructed inline from threadgroup pointers. The dot tensor uses explicit strides for column-major layout.

### 4.2 Matmul descriptor

```metal
matmul2d<
    matmul2d_descriptor(TN, TQ, NK, false, true, false,
        matmul2d_descriptor::mode::multiply_accumulate),
    execution_simdgroups<4>> mm;
```

- Output shape: TN=32 columns × TQ=32 rows
- K reduction: NK=32 per invocation
- Transpose flags: `(false, true, false)` — K is not transposed, Q is transposed, output is not transposed
- Mode: multiply-accumulate (allows iterative accumulation across k-steps)
- Execution: 4 SIMD groups (128 threads)

### 4.3 Cooperative destination tensor

```metal
auto ct = mm.template get_destination_cooperative_tensor<decltype(tk), decltype(tq0), float>();
```

The cooperative destination tensor is initialized to zero at the start of each head-pair, then accumulated over 4 k-step iterations (4 × NK=32 = D=128). After the full reduction, it is stored to the threadgroup `dot` buffer via `ct.store(td)`.

### 4.4 K-step iteration (inner loop)

```metal
FOR_UNROLL (uint i = 0; i < 4; i++) {
    auto mk = tk.slice(i*NK, 0);       // K tile at offset [i*32..i*32+31][0..31]
    auto mq = (qsel ? tq1 : tq0).slice(0, 0);
    mm.run(mk, mq, ct);
    if (i < 3) {
        qsel ^= 1u;
        stage_q(head0, (i + 1)*NK, qsel ? qtg + TQ*NK : qtg);
        threadgroup_barrier(mem_flags::mem_threadgroup);
    }
}
```

- 4 iterations cover the full D=128 reduction in 32-wide steps
- K slicing selects 32 consecutive columns from the pre-staged 128-wide K tile
- Q double-buffering: while matmul runs on one buffer, the next k-step's Q is staged into the other
- Only 3 barriers needed (none after the last iteration) — comment says "5 barriers instead of 10" compared to single-head

## 5. Post-Matmul Processing (Weighted ReLU Accumulation)

After `ct.store(td)` writes the 32×32 dot-product tile to threadgroup memory:

```metal
for (uint j = 0; j < 4; j++) {
    const uint linear = (uint)tid + j*NUM_THREADS;
    // ...
    acc[j] += max(dot[cc*TQ + r], 0.0f) * (w[head0] * args.scale);
    if (head0 + 1 < args.n_head)
        acc[j] += max(dot[cc*TQ + TM + r], 0.0f) * (w[head0 + 1] * args.scale);
}
```

Each thread accumulates weighted ReLU scores from both heads in the pair directly from the threadgroup dot buffer. The `acc[]` array persists across head-pair iterations and accumulates the full sum over all `n_head` heads.

---

## 6. Final Store with Causal Masking

```metal
const uint visible = min((args.pos0 + token + 1u) / args.ratio, args.n_comp);
*dst = comp < visible ? acc[j] : -INFINITY;
```

The final score is the accumulated weighted-ReLU sum if the compressed row is causally visible, otherwise `-INFINITY`. This implements the causal masking directly on write.

## 7. Admission Rules

### 7.1 TensorOps fires when ALL of:

1. **`g_metal4_tensor_api_enabled == 1`** — requires:
   - macOS ≥ 26.0 runtime
   - Device supports `MTLGPUFamilyMetal4`
   - Device name contains "M5", "M6", "A19", or "A20"
   - `ds4_gpu_compile_tensor_probe()` succeeds (compiles and creates a TensorOps pipeline)
   - `DS4_METAL_DISABLE_METAL4` env var is NOT set
   - `DS4_METAL_DISABLE_TENSOROPS` env var is NOT set (global rollback)

2. **`!g_quality_mode`** — `--quality` flag is not active

3. **`n_tokens >= 16`** — minimum token batch to amortize TensorOps setup

Combined in code:
```c
const bool use_nax = ds4_gpu_mpp_available() && n_tokens >= 16u;
```

Where `ds4_gpu_mpp_available()` = `g_metal4_tensor_api_enabled && !g_quality_mode`.

### 7.2 Additional implicit constraints

- `head_dim == 128` — enforced by an early exit with error message
- Valid (non-null, correctly-sized) Metal buffers for q, weights, index_comp, scores

### 7.3 Dispatch geometry (when TensorOps active)

```objc
[enc dispatchThreadgroups:MTLSizeMake(
    ((NSUInteger)n_comp + 31u) / 32u,    // ceil(n_comp / TN)
    ((NSUInteger)n_tokens + 15u) / 16u,  // ceil(n_tokens / TM)
    1)
 threadsPerThreadgroup:MTLSizeMake(128, 1, 1)];
```

## 8. Fallback Path (Legacy)

When `use_nax == false`, the host selects one of two legacy tiled kernels:

| Condition | Kernel | Tile | Threads | Precision |
|-----------|--------|------|---------|-----------|
| `g_quality_mode` | `kernel_dsv4_indexer_scores_tiled_f32` | 8 tokens × 32 rows | 32×4 (128) | Full F32 staging |
| Default (no TensorOps) | `kernel_dsv4_indexer_scores_tiled` | 8 tokens × 32 rows | 32×4 (128) | Half staging (like NAX) |

The legacy kernels:
- Use simdgroup matrix multiply (not TensorOps `matmul2d`)
- Process one head at a time (no paired-head optimization)
- Have the same threadgroup K staging pattern (32 compressed rows × 128 dims)
- Apply the same weighted-ReLU accumulation and causal masking on store
- Produce bit-identical results when staging precision matches (the F32 variant keeps full precision throughout)

### Fallback dispatch geometry:
```objc
[enc dispatchThreadgroups:MTLSizeMake(
    ((NSUInteger)n_comp + 31u) / 32u,
    ((NSUInteger)n_tokens + 7u) / 8u,    // TM=8 for legacy
    1)
 threadsPerThreadgroup:MTLSizeMake(32, 4, 1)];
```

## 9. Top-k and Indexed-Attention Are Separate

The TensorOps score kernel writes a complete `[n_tokens × n_comp]` float score matrix to device memory. The subsequent operations are completely independent kernel dispatches:

### 9.1 Pipeline sequence in `ds4.c`:

```
1. ds4_gpu_indexer_scores_prefill_tensor()    ← TensorOps or legacy
2. ds4_gpu_indexer_topk_tensor()              ← argsort-based top-k selection
3. ds4_gpu_attention_indexed_mixed_batch_heads_tensor()  ← indexed attention
```

### 9.2 Top-k selection (`ds4_gpu_indexer_topk_tensor`)

- Uses `g_argsort_f32_i32_desc_pipeline` — a bitonic/merge argsort kernel
- Operates on the full score matrix to select `DS4_N_INDEXER_TOP_K` (=512) highest-scoring compressed rows per token
- Outputs `[n_tokens × top_k]` uint32 index array
- No TensorOps involvement — pure comparison/selection logic
- Multi-pass merge for large n_comp

### 9.3 Indexed attention (`ds4_gpu_attention_indexed_mixed_batch_heads_tensor`)

- Uses the selected indices to gather KV from compressed cache
- Dispatches specialized attention kernels (8-head, 16-head dual, split variants)
- Handles raw-window attention separately
- Completely independent of the score computation method
- Has its own TensorOps variant for prefill (`prefill_dual_heads` when `ds4_gpu_mpp_available()`)

### 9.4 Confirmation

The TensorOps score kernel's output contract is identical to the legacy kernel: a float score matrix with causal masking applied. Top-k selection and indexed attention consume this matrix opaquely — they do not know or care whether TensorOps or legacy computed it.
