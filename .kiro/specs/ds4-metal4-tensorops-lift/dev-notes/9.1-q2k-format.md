# Task 9.1 — Q2_K Format Documentation

_Requirements: R7_

Source: `metal/moe.metal`, `cuda/mmq/ggml-common.h`

---

## 1. Overview

Q2_K is a 2-bit linear quantization format from the GGML/llama.cpp lineage. Each 256-element block uses 2-bit unsigned integer weights with per-16-element group scale and minimum values, plus per-block f16 scale (`d`) and minimum (`dmin`) factors.

---

## 2. Block Structure

### 2.1 C/Metal Struct Definition

```metal
// QK_K = 256 (values per super-block)
struct block_q2_K {
    uchar scales[QK_K/16];  // 16 bytes: packed 4-bit scale + 4-bit min per group
    uchar qs[QK_K/4];       // 64 bytes: 2-bit weights packed 4 per byte
    half d;                  // 2 bytes: f16 per-block scale
    half dmin;               // 2 bytes: f16 per-block minimum
};
// sizeof(block_q2_K) = 16 + 64 + 2 + 2 = 84 bytes
```

### 2.2 Block Parameters

| Parameter | Value |
|-----------|-------|
| Elements per block | 256 (QK_K) |
| Block size in bytes | 84 |
| Bits per weight | 2.625 (256×2 data + 16×8 scales + 2×16 d/dmin = 672 bits / 256 values) |
| Groups per block | 16 (each covering 16 values) |
| Natural alignment | 2-byte (half fields) |

### 2.3 Memory Layout (84 bytes)

```
Offset  Size   Field
------  ----   -----
0       16     scales[0..15] — 16 bytes, one per 16-element group
16      64     qs[0..63]     — 64 bytes, 2 bits × 256 values packed 4/byte
80      2      d             — f16 per-block scale
82      2      dmin          — f16 per-block minimum
```

---

## 3. Weight Encoding

### 3.1 2-bit Weight Packing

Four 2-bit unsigned integer values are packed per byte in `qs[]`:

```
byte[i] bits [1:0]  → weight for element 4i+0    (value 0..3)
byte[i] bits [3:2]  → weight for element 4i+1    (value 0..3)
byte[i] bits [5:4]  → weight for element 4i+2    (value 0..3)
byte[i] bits [7:6]  → weight for element 4i+3    (value 0..3)
```

### 3.2 Group Scale/Min Encoding

Each byte in `scales[g]` (g = 0..15) encodes two 4-bit values for the corresponding 16-element group:

```
scales[g] & 0x0F  → group scale factor (0..15)
scales[g] >> 4    → group minimum factor (0..15)
```

---

## 4. Dequantization Arithmetic

### 4.1 Complete Formula

For element `i` in group `g` within block `blk`:

```
value[i] = d × (scales[g] & 0xF) × shift × raw_q − dmin × (scales[g] >> 4)
```

Where:
- `d` = `float(blk->d)` (f16 → f32)
- `dmin` = `float(blk->dmin)` (f16 → f32)
- `raw_q` = 2-bit unsigned integer (0, 1, 2, or 3) from `qs[]`
- `shift` = position-dependent normalizer: {1, 1/4, 1/16, 1/64} depending on which pair of bits within the packed byte is being addressed
- Group g covers elements [16g .. 16g+15]

### 4.2 Metal Shader Dequant (Reference)

```metal
template <typename type4x4>
void dequantize_q2_K(device const block_q2_K *xb, short il, thread type4x4 & reg) {
    const float d = xb->d;
    const float min = xb->dmin;
    device const uint8_t * q = (device const uint8_t *)xb->qs;
    float dl, ml;
    uint8_t sc = xb->scales[il];

    q = q + 32*(il/8) + 16*(il&1);
    il = (il/2)%4;

    half  coef = il>1 ? (il>2 ? 1/64.h : 1/16.h) : (il>0 ? 1/4.h : 1.h);
    uchar mask = il>1 ? (il>2 ? 192    : 48)     : (il>0 ? 12    : 3);
    dl = d * (sc & 0xF) * coef, ml = min * (sc >> 4);
    for (int i = 0; i < 16; ++i) {
        reg[i/4][i%4] = dl * (q[i] & mask) - ml;
    }
}
```

### 4.3 Key Properties

- **Asymmetric quantization**: The formula has both a multiplicative term (`d × scale × q`) and a subtractive offset (`dmin × min`). This is NOT symmetric around zero.
- **Group-varying parameters**: Both the scale and min factors change every 16 elements within a block.
- **Position-dependent extraction**: The bit-shift/mask required to extract the 2-bit weight depends on the element's position within the byte.

## 5. Native Metal int2 Tensor Compatibility Assessment

### 5.1 Fundamental Incompatibility

**Native Metal `int2` tensors cannot represent Q2_K directly.**

A native int2/uint2 tensor type assumes a uniform linear mapping:
```
x = scale × int2_value + zero_point
```

Q2_K requires:
```
x = d × group_scale × position_shift × q − dmin × group_min
```

The incompatibility has three dimensions:
1. **Group-varying scale** (16 groups per block, each with its own 4-bit scale) — cannot be expressed as a single per-tensor or per-block scale
2. **Group-varying zero point** (16 groups per block, each with its own 4-bit min) — cannot be expressed as a single zero_point
3. **Position-dependent bit extraction** — the shift factor depends on which 2-bit pair within the byte, adding another axis of variation

### 5.2 What Would Be Needed

To use TensorOps/`matmul2d` with Q2_K, the code must:
1. **Custom-dequantize** packed blocks into f16 threadgroup tiles
2. Feed the f16 result to `matmul2d`

This is exactly what the existing `kernel_mul_mm_id_q2_K_f16_mpp` and related kernels do.

---

## 6. Contrast with Native-Compatible Formats

| Property | Q2_K | Hypothetical native int2 |
|----------|------|--------------------------|
| Scale granularity | Per 16 elements (× per-block) | Per tensor or per-block |
| Zero point | Per 16 elements | Per tensor or per-block |
| Bit extraction | Position-dependent mask+shift | Implicit hardware unpack |
| Value interpretation | Unsigned + asymmetric affine | Signed/unsigned + uniform affine |
| Can express with `scale×q+zp` | **No** | Yes (by definition) |

---

## 7. Summary

Q2_K is a well-engineered asymmetric quantization with fine-grained (per-16-element) scale and offset parameters. This fine granularity is what gives it reasonable quality at 2.625 bpw, but it is precisely what makes it incompatible with any native tensor type that assumes uniform per-block or per-tensor dequantization parameters. The only viable TensorOps path is custom dequantization into f16 cooperative/threadgroup tiles before matmul.
